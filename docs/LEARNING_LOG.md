# Personal Learning Log

Use this file as the dated record of your actual work. Keep the course's episode status in [PROGRESS_TRACKER.md](../PROGRESS_TRACKER.md); use this log for evidence, blockers, and next actions.

> No lesson is pre-marked complete. Record only sessions you have actually completed.

## Session template

Copy this block for each study session:

~~~markdown
### YYYY-MM-DD · Episode NN — Topic

- **Session type:** Watch / Rebuild / Experiment / Review
- **Practice asset used:** exact repository filename or external connector
- **What I reproduced:**
- **What I changed/tested:**
- **Validation:** row count / types / keys / totals / refresh / error cases
- **Evidence:** relative path to PBIX, workbook, screenshot, or M snippet
- **What I can explain now:**
- **Blocker / uncertainty:**
- **Next action:**
- **Confidence:** 1 (low) – 5 (can teach it)
~~~

## Review cadence

| When | Review action |
|---|---|
| Same session | Rebuild the main transformation once |
| 2–3 days later | Recall the concept and explain the decisions |
| 7 days later | Rebuild a key step without following the video |
| End of phase | Complete the phase skill gate in the roadmap |

## Evidence folder suggestion

Keep personal evidence separate from original course source files:

~~~text
learning-evidence/
├── phase-01-foundations/
├── phase-02-acquisition/
├── phase-03-extraction/
├── phase-04-governance/
├── phase-05-transformation/
├── phase-06-case-studies/
└── phase-07-m-language/
~~~

Do not commit private credentials, licensed source files you are not permitted to redistribute, or personal data. A short explanation plus a small synthetic sample is often better evidence than a full copy of the original data.
